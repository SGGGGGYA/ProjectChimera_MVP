```
    ┌──────────────────┐    ┌─────────────────────────┐
    │  BreakdownDatabase│    │ QuirkTriggerSystem      │
    │  (初始化时填充)    │    │ (static)                │
    │  - entries[]      │    │ - CheckTriggers         │
    │  - Get(id)        │    │ - ApplyQuirkEffect      │
    └──────────────────┘    └────────┬────────────────┘
                                     │
                                     │ 在 cuiRuo / buXiangYuGan / ziNue 等 quirk 中
                                     │ 调 StressManager.AddStress
                                     │
                                     └──────⚠️ 循环依赖！
```

**循环依赖**示例流程：
```
StressManager.AddStress
  → 触发 OnStress
  → QuirkTriggerSystem.CheckTriggers(OnStress)
  → ApplyQuirkEffect (例如 "cuiRuo" quirk)
  → StressManager.AddStress (递归)
```

**实际影响**：
- `QuirkTriggerSystem.cs:78-90` 的 cuiRuo/buXiangYuGan/ziNue 三个 quirk 会**递归** AddStress
- 没有递归深度限制，理论可能死循环
- 实际被 `cooldown` 防住（CD=1 后下回合不再触发）
- 但这种"在压力系统内调压力系统"的设计本身就是 anti-pattern

## 8. 三个核心数据流

### 数据流 A：回合循环

```
TurnManager.StartNextTurn
  └─► QuirkTriggerSystem.CheckTriggers(TurnStart)
  └─► TurnManager.ExecuteTurn
        └─► BattleManager.ExecuteAction
              └─► Command.Execute(ctx)
                    ├─► CombatSystem.IsHit/IsCrit
                    ├─► CombatSystem.CalculateDamage
                    ├─► UnitData.TakeDamage → StressManager.AddStress → CheckResolve
                    │                                          └─► QuirkTriggerSystem.CheckTriggers(OnStress)
                    └─► QuirkTriggerSystem.CheckTriggers(OnHit/OnCrit/OnTakeDamage/...)
  └─► TurnManager.EndTurn
        └─► QuirkTriggerSystem.CheckTriggers(TurnEnd)
        └─► UnitData.TickModifiers / TickQuirkCooldowns
        └─► StressManager.CheckResolve
```

### 数据流 B：单位数据生成

```
GameManager.playerTeamData (List<UnitBattleData>)
  └─► BattleSetup.Awake
        ├─► CloneUnitBattleData
        └─► BattleSetup.CreateUnit
              ├─► GameManager.GetClassDefinition(unitName)  // 查 classData
              ├─► Instantiate(universalCharacterPrefab)
              ├─► UnitData.VIT/STR/... 赋值
              ├─► UnitData.classData = classDef
              ├─► UnitData.skills = classDef.skillPool
              └─► EnemyAIEngine.Reset(unit)
```

### 数据流 C：存档/读档

```
GameManager.SaveGame
  └─► SaveManager.Save(SaveData)  // 序列化含 playerTeam, inventory, gold, dungeonFloor

GameManager.LoadGame
  └─► SaveManager.Load
        └─► DungeonGenerator.GenerateMap(floor)
        └─► UnitData 重新生成 (走数据流 B)
```

## 9. 关键问题

### ⚠️ 循环依赖 1：`StressManager ↔ QuirkTriggerSystem`

**位置**：
- `StressManager.cs:56` → 调 `QuirkTriggerSystem.CheckTriggers(OnStress)`
- `QuirkTriggerSystem.cs:78,84,90,108,123` → 调 `StressManager.AddStress/ReduceStress`

**后果**：
- 压力 → 怪癖 → 压力 ... 递归链
- 测试需要 mock 双方
- 改一边要确认另一边不受影响

**建议重构**：
- 把 QuirkTriggerSystem 的 stress 类效果改成"标记"而不是直接调 StressManager
- StressManager 在 OnResolve 后统一结算

### ⚠️ 循环依赖 2：`TurnManager ↔ BattleManager`

**位置**：
- `TurnManager` 4 次 `FindObjectOfType<BattleManager>`（隐式依赖）
- `BattleManager` 5+ 次读 `TurnManager.Instance.currentUnit`（强依赖）

**建议重构**：
- 引入 `BattleContext` 单例，持有 `bm + tm + 双方单位`
- TurnManager 和 BattleManager 都从 `BattleContext` 取引用

### ⚠️ 隐式依赖：`UnitData` 知道太多

`UnitData` 类现在 700+ 行，包括：
- 战斗逻辑（GetFinalStat, TakeDamage, TickModifiers）
- 动画控制（Play, Revive, CleanupForRetreat）
- UI 引用（hpBarFollower, stressBarFollower, selectCircle）
- 命名系统（isNamed, namingQuirk, exclusiveSkill, stressCapBonus）
- 阵营判定（isPlayer）
- 存档数据（currentHP, stress, level, currentExp, equipped, quirks）

**建议拆分**：
- `UnitData`（核心数据）
- `UnitCombat`（战斗 + 动画）
- `UnitUI`（HP/Stress bar 引用 + 选中光圈）
- `UnitNaming`（命名系统）
- `UnitSaveState`（持久化结构）

## 10. 依赖层级理想图（重构目标）

```
Layer 0:  纯数据     PrimaryAttributes, Equipment, Quirk, StatusEffect
            │
Layer 1:  静态工具  CombatSystem, Equipment.GetBuyPrice, Quirk.GetFlatMod
            │
Layer 2:  实体      UnitData (组合 Layer 0)
            │
Layer 3:  系统     StressManager, QuirkTriggerSystem, TurnManager
            │
Layer 4:  协调     BattleManager, EnemyAIEngine (接收 UnitData, 调 Layer 3)
            │
Layer 5:  入口     GameManager, BattleSetup (持有 Layer 4)
            │
Layer 6:  UI       UI Controllers
```

**当前问题**：
- CombatSystem 在 Layer 1（应该是纯函数）但接收 `UnitData`（Layer 2），跨层
- StressManager / QuirkTriggerSystem 互相依赖，违反层级
- UI Controllers 通过 FindObjectOfType 拿 BattleManager，违反"向下依赖"原则

## ✅ 循环依赖 #2 修复说明（2026-06-09 完成）

**目标**：消除 `TurnManager ↔ BattleManager` 双向硬依赖（11 处 `TurnManager.Instance` + 3 处 `FindObjectOfType<BattleManager>` + 1 处 `TurnManager.Instance?.EndTurn()`）。

**方案**：接口注入 + 事件总线（不引入 DI 框架，保持手写装配的简单性）

### 新增文件（3 个）
- [ITurnStateProvider.cs](../../ProjectChimera_MVP/ProjectChimera_MVP/Assets/Scripts/Battle/ITurnStateProvider.cs) — BattleManager 用来读 TurnManager 状态的接口（CurrentUnit、IsPlayerTurn、RoundCount、IsBattleOver + 3 个 event）
- [IBattleContext.cs](../../ProjectChimera_MVP/ProjectChimera_MVP/Assets/Scripts/Battle/IBattleContext.cs) — TurnManager 用来调 BattleManager UI/编队的接口（PlayerUnits、EnemyUnits、GetFirstAlive、SpawnDamagePopup、SpawnTextPopup、RawBattleManager 逃生通道 + NullBattleContext 默认实现）
- [BattleEvents.cs](../../ProjectChimera_MVP/ProjectChimera_MVP/Assets/Scripts/Battle/BattleEvents.cs) — 跨管理器的全局事件总线（OnTurnStarted/OnTurnEnded/OnRoundStarted/OnEndTurnRequested/OnEnemyTurnCompleted/OnUnitKilled/OnBattleEnded）

### 修改文件
