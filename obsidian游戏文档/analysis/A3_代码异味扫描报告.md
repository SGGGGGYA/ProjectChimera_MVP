## 🔴 致命级（4 项）

### 1. 三套不同的"防御"字段名

```
UnitData.cs:15      → public int baseDefense = 5;        // 用于 GetFinalStat
ClassDefinition.cs:13 → public int baseDEF = 5;          // 职业模板
UnitBattleData.cs:21  → public int DEF = 5;              // 持久化数据
BattleManager.cs:1366 → data.DEF = unit.baseDefense;     // 跨类赋值
```

**问题**：
- 三个字段名代表**同一个**概念
- BattleManager 回写持久化时手动映射 (`data.DEF = unit.baseDefense`)，漏一个就丢数据
- 阅读 `unit.baseDefense` 时不知道这跟 `unit.DEF_Effective` 什么关系

**影响**：在序列化/反序列化、跨层数据传递时容易漏字段。当前已有 `GameManager.CloneUnitBattleData` 的 `defense` 字段被遗漏的迹象。

**修复**（统一到一个名字 + 一个事实源）：
```csharp
// 建议：统一叫 DEF，全部用 UnitData.DEF_Effective 访问
public int DEF => GetFinalStat(StatType.DEF);
```

### ② StressManager ↔ QuirkTriggerSystem 循环依赖（2026-06-09 完成）

**问题**：`StressManager.AddStress` 末尾调用 `QuirkTriggerSystem.CheckTriggers(OnStress)`；cuiRuo / buXiangYuGan / ziNue 在 `ApplyQuirkEffect` 里反向调用 `AddStress`。单凭"每怪癖 1 回合 CD"兜不住多个不同 id 的"加压"怪癖同时存在时的链式触发（cuiRuo → +2 → CheckTriggers → buXiangYuGan → +5 → CheckTriggers → ... → StackOverflow）。

**修复**：
- `StressManager.AddStress` 加入静态重入计数器 `addStressReentryDepth`，**只有最外层**调用才触发 `CheckTriggers(OnStress)`，内层只更新压力数值
- 新增公开 API `StressManager.DispatchStressTriggers(unit)`，绕过重入守卫，供测试/外部代码显式触发
- `QuirkTriggerSystemTests.cs` 新增 3 个回归测试：单 quirk 递归不爆栈、多 quirk 并发不链式死循环、DispatchStressTriggers 入口可重复调用

**详细 diff**：[StressManager.cs:11-21](../../ProjectChimera_MVP/ProjectChimera_MVP/Assets/Scripts/Stress/StressManager.cs#L11-L21)（重入计数器注释）、[StressManager.cs:68-81](../../ProjectChimera_MVP/ProjectChimera_MVP/Assets/Scripts/Stress/StressManager.cs#L68-L81)（守卫块）、[StressManager.cs:83-93](../../ProjectChimera_MVP/ProjectChimera_MVP/Assets/Scripts/Stress/StressManager.cs#L83-L93)（DispatchStressTriggers）
