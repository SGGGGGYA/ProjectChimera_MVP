## 一、系统需求分析

### 1.1 现状评估

| 项目 | 当前实现 | 缺失/不足 |
|:---|:---|:---|
| 压力累积 | UnitData.AddStress() — 硬上限100，无条件累加 | 无压力抗性修正、无事件类型区分、无递减收益 |
| 压力缓解 | UnitData.ReduceStress() — 仅减数值 | 无系统化缓解途径、无战斗内外区分 |
| 压力崩溃 | TurnManager.cs:90-119 — 随机攻击+跳过回合 | 仅1种结果，无美德/折磨区分、无叙事上下文 |
| UI表现 | GetStressBar() — 文本颜色条 | 无专用UI组件、无崩溃动画/面板、无状态指示器 |
| 数值配置 | 硬编码在代码中 | 无可调整的配置表 |

### 1.2 设计目标

压力系统需服务于《Project Chimera》的核心体验：**残酷资源管理下的英雄养成与高策略性战术战斗**。具体目标：

1. **情感张力** — 压力值成为玩家策略决策的核心参数，高压状态带来戏剧性转折
2. **策略深度** — 压力管理成为与HP管理并行的第二资源体系
3. **叙事生成** — 美德/折磨事件作为"单人故事生成器"的核心触发机制
4. **反馈闭环** — 压力与战斗表现、资源消耗、队伍构成形成可感知的因果链

### 1.3 核心设计原则

| 原则 | 说明 |
|:---|:---|
| 可预测性 | 玩家应能合理预判压力增减的结果，避免纯运气设计 |
| 非对称收益 | 高风险（高压）操作应提供高回报窗口 |
| 边际效用递减 | 压力抗性等百分比属性遵循衰减上限 |
| 上下文感知 | 崩溃结果应与当前情境、角色特质关联 |

## 二、核心功能模块设计

### 2.1 模块架构

```
[压力系统] — 包含6个子模块
├── 2.1 压力值管理器 (StressManager)
│   ├── 压力累积接口 (含抗性修正)
│   ├── 压力缓解接口
│   ├── 压力阈值检测
│   └── 压力溢出处理
├── 2.2 压力事件源 (StressEventSource)
│   ├── 战斗事件源（受击/击杀/队友阵亡/暴击/闪避等）
│   ├── 环境事件源（地形/天气/时间）
│   └── 策略事件源（技能代价/装备诅咒）
├── 2.3 崩溃判定系统 (BreakdownResolver)
│   ├── 美德/折磨二相判定
│   ├── 上下文适配池（叙事标签匹配）
│   ├── 崩溃效果执行
│   └── 状态持续/恢复逻辑
├── 2.4 压力抗性系统 (StressResist)
│   ├── 基础抗性（职业/等级）
│   ├── 装备/怪癖修正
│   └── 累积递减保护
├── 2.5 压力UI表现层 (StressUI)
│   ├── 压力条组件
│   ├── 状态指示器
│   ├── 崩溃动画/面板
│   └── 音效触发
└── 2.6 压力数据配置 (StressConfig)
    ├── 事件基础值表
    ├── 崩溃结果池
    ├── 抗性衰减曲线
    └── UI参数
```

### 2.2 模块间通信

```
UnitData (数据层)
  ├── stress: int (0-100，存储当前值)
  ├── breakdownState: BreakdownState (None/Virtue/Affliction)
  ├── breakdownId: string (当前崩溃效果ID)
  └── stressResist: float (压力抗性百分比，0-90%)

BattleManager (战斗层)
  ├── 调用 AddStress() 触发压力事件
  ├── 调用 ResolveBreakdown() 处理崩溃
  └── 监听压力变化事件更新UI

TurnManager (回合层) — 修改现有崩溃处理
  ├── 委托给 StressManager 处理压力>=100
  └── 根据崩溃类型决定是否跳过/改变行动

GameManager (全局层)
  ├── 世界地图调用 ReduceStress() 进行休整减压
  └── 每日结算时调用压力衰减
```

## 四、算法实现方案

### 4.1 压力累积算法

```
输入: rawAmount (原始压力值), unit (目标UnitData)
输出: actualAmount (实际增加的压力值)

1. 计算抗性修正:
   resistRate = unit.stressResistRate
   if (resistRate > StressConfig.maxResist) resistRate = StressConfig.maxResist
   
2. 边际效用递减（当抗性>60%时，超出部分仅生效50%）:
   if (resistRate > resistDiminishThreshold)
   {
       effectiveResist = resistDiminishThreshold 
                         + (resistRate - resistDiminishThreshold) * 0.5f
   }
   else effectiveResist = resistRate
   
3. 计算实际增量:
   actualAmount = max(1, round(rawAmount * (1 - effectiveResist)))
   
4. 应用压力增量:
   unit.stress = min(stress + actualAmount, StressConfig.maxStress + overflowBuffer)
   
5. 如果 stress >= maxStress → 触发崩溃判定
```

### 4.2 崩溃判定算法

```
输入: unit (触发崩溃的单位)
输出: BreakdownEntry (选中的崩溃效果)

1. 确定美德/折磨二相:
   virtueProbability = StressConfig.virtueChance
   virtueProbability += unit.正面怪癖数量 * StressConfig.virtueChancePerPositiveQuirk
   virtueProbability += (unit.stressResistRate * 100 / 10) * StressConfig.virtueChancePerStressResist
   
   isVirtue = Random.value < virtueProbability

2. 上下文感知抽取:
   a. 收集unit最近的StressEvent记录（最近5条）
   b. 从事件标签中统计出现频率最高的top-3标签
   c. 在匹配标签的崩溃池中按权重抽取（80%概率）
   d. 从普通池按权重抽取（20%概率兜底）

3. 执行崩溃:
   unit.breakdownState = isVirtue ? Virtue : Affliction
   unit.currentBreakdownId = selectedEntry.id
   unit.breakdownDurationRemaining = Random.Range(min, max)
   
   根据 selectedEntry.effectType 执行对应效果:
   - skipTurn: 跳过当前/下次行动
   - randomAttack: 随机选目标执行攻击
   - statModPercent: 应用属性修正
   - stressChange: 调整压力值
   - selfDamage: 对自己造成伤害
```

### 4.3 崩溃状态Tick算法

```
每回合结束时调用（在 TurnManager.EndTurn 或 UnitData.TickStatusEffects 中）:

1. if (unit.breakdownState == None) return

2. unit.breakdownDurationRemaining--
3. 每回合执行持续效果:
   - 如果是折磨Hopeless: 每回合stress +5
   - 如果是美德Courageous: 每回合stress -3
   
4. if (unit.breakdownDurationRemaining <= 0):
   - 清除崩溃状态
   - unit.breakdownState = None
   - 记录日志: "{unitName} 从[崩溃效果]中恢复"
```

### 4.4 压力缓解途径计算

| 途径 | 触发时机 | 计算逻辑 | 限制条件 |
|:---|:---|:---|:---|
| 击杀敌人 | 战斗中每次击杀 | -5 基础值 | 仅击杀人形/精英单位 |
| 打出暴击 | 每次暴击 | -5 基础值 | 无 |
| 队友暴击 | 每次队友暴击 | -3 基础值 | 同一队友每回合最多触发1次 |
| 队友阵亡 | 战斗中队友死亡 | +20 基础值 | 命名英雄阵亡额外+10 |
| 被暴击 | 每次被暴击 | +5 (叠加在受击+2之上) | 无 |
| 未命中 | 每次攻击Miss | +2 基础值 | 近战职业额外+1挫败感 |
| 扎营休整 | 扎营时 | -15 基础值 | 消耗1扎营资源 |
| 城镇休整 | 城镇每日结算 | -5 自然恢复 | 每宏观天1次 |
| 酒馆消费 | 城镇确认消耗 | -15 消费减压 | 消耗金币，每访1次 |
| 技能/装备 | 特定技能触发 | 按技能定义 | 按技能冷却 |

}
